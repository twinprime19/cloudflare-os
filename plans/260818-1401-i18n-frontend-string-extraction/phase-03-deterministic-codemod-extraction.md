# Phase 3: Deterministic Codemod Extraction

## Overview

Zero-LLM-cost mechanical wrap of the deterministic majority (target 60–80% of ~1,000–1,500 strings). ts-morph codemod run over `packages/workshop-frontend/src`. Codemod authored by high-quality model; running it costs nothing. Run immediately after a fresh upstream sync (see plan.md Dependencies).

## Requirements

- Functional: JSX text nodes containing natural language → `<Trans>...</Trans>` (children byte-identical inside wrap); whitelisted string-literal attributes (`placeholder`, `title`, `aria-label`, `aria-description`, `alt`) → `` t`...` `` (core macro, global instance — avoids hook-injection complexity); imports auto-added.
- Non-functional: idempotent (re-run produces no further changes); conservative — skip anything ambiguous, leave for Phase 4.

## Architecture

- `scripts/i18n-codemod/` (native TS, colocated tests per repo convention from commit 657aa96):
  - `detect.ts` — shared detection module (also consumed by the Phase 2 guard): what counts as user-facing text. Heuristics: contains letters + at least one space OR is a capitalized word ≥4 chars in a whitelisted attr; excludes: no-letter strings, URLs, paths, camelCase/snake_case identifiers, template-only expressions, `data-*`/`className`/`key`/`id` attrs, `*.test.tsx`, generated route files.
  - `wrap-jsx-text.ts`, `wrap-attrs.ts`, `imports.ts`, `run.ts` (CLI: `--dry-run`, `--files glob`, `--report out.json`).
- Skip-and-report list: mixed JSX text + inline expressions forming sentences, conditional strings, concatenations, plural patterns → emitted to `codemod-residue-report.json` as Phase 4 input.

## Related Code Files

- Create: `scripts/i18n-codemod/*.ts` + colocated `*.test.ts`
- Modify: bulk of `packages/workshop-frontend/src/**/*.tsx` (mechanical, generated by codemod)

## Implementation Steps

1. Confirm clean sync point with upstream; confirm `260815-1442` coordination (plan.md Dependencies).
2. Write codemod + unit tests on fixture snippets (each transform rule + each exclusion rule).
3. `--dry-run --report`: review counts vs scout estimate (~536 JSX text, ~292 attrs); sample 20 random planned edits manually.
4. Run for real. `pnpm i18n:extract` → catalog populated. Build + typecheck + vitest.
5. Idempotency check: re-run codemod → zero changes.
6. Guard/detector re-run → remaining candidates list == residue report (consistency check between the two consumers of `detect.ts`).
7. Spot-review diff sample (orchestrator + code-reviewer subagent on a sampled diff, not full 250-file dump).

## Risk Assessment

- Over-wrapping non-UI strings → conservative heuristics + dry-run sampling + reviewer pass; rules fixed centrally in `detect.ts`, codemod re-run (idempotency makes this cheap).
- `<Trans>` around whitespace-significant JSX changes rendering → preserve exact children including whitespace; add fixture test.
- Attr `t` with global instance vs future SSR: workshop-frontend is a client SPA (Vite, TanStack Router) — no SSR concern now; noted for the record.
- Huge diff unreviewable → review by sampling + verification tooling, not eyeballs; this is the accepted trade of mechanical transforms.
