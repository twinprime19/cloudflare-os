# Workspace idle pause

An open workspace tab keeps its Overseer Durable Object (and the user's UserDurableObject) in memory through the live RPC WebSocket, and idle tabs were 94% of billed DO duration. The frontend closes that socket on purpose when nobody is using the tab, and the Overseer ends sessions that have stopped calling it, so a tab that is frozen, asleep, or gone cannot hold a workspace awake either.

**What pauses.** The whole RPC socket, for the workspace route (`/workspace/<id>`; `/gadget/<id>` redirects there), never individual stubs. The home page has no idle timer of its own. The Worker session ends, every DO stub behind it is released, and the Overseer and User DOs go idle within their normal grace period. Calls issued while paused queue on the placeholder stub and flush on resume, so chat history, the composer draft, and the gadget iframe (with its in-frame state) all survive.

**Thresholds.** Hidden tab: 5 minutes. Visible tab with no input: 15 minutes. Mouse movement is not input; clicks, keys, touch, wheel, and scroll defer the pause in the page, and inside the sandboxed gadget iframe the bootstrap forwards clicks, keys, touch, and wheel to the parent as an `activity` message (at most one per 10 seconds), which covers scrolling by trackpad, scrollbar, keys, or touch. A focused but untouched iframe is idle. No pause while the selected chat is streaming. An unanswered observer-config dialog does not defer the pause — it holds the workspace's DO open inside `openGadget`, so the pause cancels the dialog and the half-open tab parks on the Paused chip (no error page); clicking the chip re-opens the workspace, which asks again. The server ends a parked open too: if the workspace's lease expires while a dialog is still unanswered, the Worker closes the socket with the idle code and the tab parks the same way. Constants live in `packages/workshop-frontend/src/useWorkspaceIdle.ts`; the pause flag and reconnect parking live in `connectionPause.ts`, hooked into `main.tsx` and `GadgetUI.tsx`.

**Resume is deliberate.** Nothing wakes a paused workspace by itself: not the tab becoming visible, not clicking around, not typing. Reading what is already on screen costs nothing, and a revived Durable Object stays awake until the next threshold. What resumes: sending from the composer (the message goes out after the reconnect), approving or denying an action or connection request, clicking the Paused chip, or leaving the workspace. Anything else done while paused (a gadget button, a code edit, opening another gadget view) queues until one of those happens; the chip is the hint, and it is present on the use-only view too.

**What the user sees.** While paused, the top-bar chip reads "Paused — click to reconnect" and is a button. It renders both in the workspace editor's header and in the app shell's top bar (both read the flag through `useConnectionPaused`), so a pause the server starts while the user sits on another page — the home list and the rail each hold an Overseer stub open for the Share modal's lifetime — still has a resume control. The usual "Reconnecting…" chip appears only during the resume itself.

**Server lease.** Each Overseer holds a 15-minute client-activity lease, armed by the first browser RPC of an incarnation and renewed by later browser RPCs and by the end of an agent turn; DO→client pushes, `ping()`, gatekeeper callbacks, and internal calls never renew it. The DO's own alarm checks the lease and ends the session with `ctx.abort`, so nothing depends on a Worker timer that may never run. The Worker turns that into a `4001` close (`SESSION_IDLE_CLOSE_CODE` in `workshop-shared/src/api.ts`) only when the expiring workspace was that session's last live one; with another workspace still live on the socket it logs and leaves the socket alone. The socket URL carries `?open=initial|redial|resume`, which the session log records, so an automatic redial is distinguishable from a deliberate resume.

**The browser always parks on 4001.** A 4001 close of the current socket parks on the Paused chip unconditionally — busy, visible, or just typed in makes no difference, and the tab never dials back on its own. A close from a socket the reconnect loop already replaced is ignored, so a late one cannot park a healthy connection. Every other close code is an ordinary outage. Worst case for a present-but-quiet user: one click.

**Kill switch.** Set the key `.sessionLease` to `off` in the `BLUEPRINTS` KV namespace and no lease ever expires a session; it takes effect within about 60 seconds (KV cache TTL) plus one alarm period, with no redeploy. The browser's 4001 handling is inert while nothing sends the code.

**Verifying on staging.** Query `durableObjectsPeriodicGroups` with dimensions `namespaceId, objectId` (objectId equals the `<id>` in the workspace URL) and sum `duration, activeTime, subrequests, inboundWebsocketMsgCount`. A paused workspace's `activeTime` flatlines within about two minutes; the user's UserDurableObject too.
